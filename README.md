🆕 What's New in v2.0
🎯 Dual Advocate System
The system now recognizes two distinct advocate types with different eligibility rules, visibility permissions, and presentation to sales teams. This enables proper tracking and future flexibility for differentiated reward structures.

1. Advocate Type Classification
Every customer is automatically classified as either a Project Advocate (owns in target project) or Brand Advocate (owns in other developer projects)

2. Validation on Submission
Backend validates advocate type selection matches customer profile. Auto-corrects when possible, rejects when invalid (e.g., cross-developer attempts)

3. Targeted Eligibility
Project Advocates can only refer to their own project. Brand Advocates can refer to any new project by their developer

4. Sales Communication
Sales teams receive context: "Referred by a fellow resident" vs "Referred by an existing Oscar customer"
